# Native Item and reconciliation implementation

This ledger describes the delivered code boundaries. Actual test reports, image
identities and operational receipts are separate source-qualified evidence; a
design case or an earlier PASS is not reassigned to the current implementation.

## Authority and execution

UUIDv7 IDs are lossless decimal strings, with exact native/historical aliases.
Registry changes and their journal share the domain transaction. Sealed manifests
retain File IDs outside the compact core. Stable File identity, expected digest,
current copy evidence and disposable search observations remain separate.

Inventory-backed producer publication hashes declared members off the writer,
retains compact pins and supports native exact member inputs without waiting for
FTS. Small legacy outputs/inputs remain supported. Original Job/Attempt identities,
resource ownership, cancellation, recovery, callbacks and result contracts remain
authoritative. Reconciliation and index maintenance never create scientific Jobs.

Explicit plan/validate/apply supports current and v1 asset adapters, existing-source
adoption, additive file/historical bindings and external typed imports. Server-created
proofs, source identity, grants and contract context are rechecked. Key/source
conflicts, duplicate member keys and changed files fail before an atomic apply.
Original historical bodies/availability and existing account/token rows stay intact.
Applied receipts replay without reopening moved source files. Scientific metadata
is declared/unverified; no numerical, GPU or simulator acceptance is inferred.

## Discovery and software

Search uses exact/prefix/lexical tiers, stable MVCC pages, current/all revisions,
origin/native-kind/relation filters and bounded at-least waits. HMAC cursors bind
the query, source generation, actor and access context. Historical current discovery
does not duplicate old snapshots; exact aliases still read the original snapshot.

Relations page exact Scenario/Job/workflow/asset and software combinations, including
indexed reverse use. Profile reads reconstruct the accepted hash from registered
definitions or frozen Job evidence rather than substituting a new definition.
Runtime observations adopt Dependency Items, retain incomplete observations and
expose representative dependencies by default. Explicit host inventories cover only
selected roots under the configured dependency directory and require current grants
for byte reads. Unrecorded, partial and missing sources are distinct.

The Dashboard uses a compact bootstrap, server-backed kind pages, lazy exact details
and relation/file/log continuations. Activity has a separate actual-interval/eligible
registration rollup, so a catalog page is not treated as the complete activity history.
The existing UI, authentication relay and legacy catalog route remain compatible.

## Logs and maintenance

Log streams retain effect/Attempt/stage/source-generation identity and raw offsets.
Independent collectors release execution ownership before sealing logs; per-stream,
global capture/spool and free-space budgets bound private I/O. Selected returned,
closed generations can expire with persistent gap evidence. Raw provider/spool
copies and FTS bodies are removed without deleting producer containers or Jobs.
Legacy read adapters cannot bypass expiry.

An online rebuild projects a shadow generation beside the active index and switches
only after source-qualified catch-up. Existing readers retain their handles and old
cursors expire. Durable task failures/progress can be inspected and retried.
Explicit cleanup preserves the active index and a ten-minute retired-generation
grace period. An authority anchor rejects an index ahead of/restored against its
source. Offline backfill/rebuild and explicit large-file verification remain available.

## Installation and evidence boundaries

Cumulative schema 4 -> 5 -> 6 -> 7 steps preserve originals and exact identities.
Private snapshots include authoritative manifests, source proofs, raw spool and
host Runtime inventories; disposable indexes are rebuilt. Rollback guards compare
full binding/plan/import/retention identity and evidence. Streamed single-store
portable relocation preserves payload metadata and logical machine/store IDs;
unsupported clone/multi-store remapping is rejected with an explicit repair path.

All six MCP groups, native guides, Dashboard relay and independently pinned Loom
Use are updated together. The native CPU image and packaged client require separate
execution acceptance. Scale fixtures include the opt-in 100k Item / 1m File / 10m
bounded log-document envelope with raw-byte/overlap disclosure. Actual scientific
libraries, tensor values, GPU/Sim behavior, reboot and external network/Sharing
remain separately scoped acceptance, never inferred from structural tests.

Operational configuration, sampled research metadata, credentials and measured
host evidence are private and must not be committed to this source repository.
